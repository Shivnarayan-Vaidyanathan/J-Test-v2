# SEC-001 Remediation Evidence

## Finding
Hard-coded Gemini API key

## Original Severity
Critical

## CWE
CWE-798 — Use of Hard-coded Credentials

## OWASP
A02:2021 — Cryptographic Failures

## Original Location
J-Test/Controllers/UserStoryDescription.cs

## Agent Remediation
Removed the hard-coded Gemini API key from application source.

The Gemini API key is now retrieved through ASP.NET Core IConfiguration
using the configuration key:

Gemini:ApiKey

Local development uses ASP.NET Core User Secrets.

No real Gemini credential is stored in the repository.

## Files Changed
- J-Test/Controllers/UserStoryDescription.cs
- J-Test/J-Test.csproj

## Secret Rotation
Previously exposed Gemini credential was treated as compromised and
rotated/revoked.

## Validation
- dotnet restore
- dotnet build
- source search for hard-coded Gemini credential
- application configuration failure-path validation

## Functional Impact
No intended functional change.

Gemini test-case generation continues to use the configured Gemini API
credential.
