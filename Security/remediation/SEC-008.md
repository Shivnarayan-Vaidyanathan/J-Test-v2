# SEC-008 – Server-Side Request Forgery (SSRF)

## Classification

Severity: High

CWE: CWE-918 – Server-Side Request Forgery (SSRF)

OWASP Top 10: A10:2021 – Server-Side Request Forgery

## Original Issue

The Jira integration constructed an outbound URL using the Jira
domain stored in the Details table without validating the destination.

The backend subsequently issued the request using HttpClient.

This allowed stored user-controlled domain data to influence the
destination of a server-side HTTP request.

## Remediation

Implemented an explicit Jira hostname allowlist using application
configuration.

Only approved Jira hosts are accepted.

The implementation:

- rejects blank domains
- rejects URL schemes
- rejects paths, query strings and fragments
- rejects user-info and explicit ports
- rejects localhost
- rejects IPv4 and IPv6 literals
- normalizes hostnames
- performs exact case-insensitive allowlist matching
- constructs the final HTTPS URI using UriBuilder
- uses a fixed Jira API path
- URL-encodes the JQL query

Approved Jira hosts:

- shivnarayan2704.atlassian.net
- shivnarayan2799.atlassian.net

## Positive Test

An existing approved Jira credential was selected.

Result:

The Jira request succeeded and existing Jira import functionality
continued to operate.

PASS

## Negative Tests

The following destinations were tested and rejected before an outbound
request was made:

- localhost
- 127.0.0.1
- 169.254.169.254
- evil.com
- another.atlassian.net
- shivnarayan2704.atlassian.net.evil.com
- https://shivnarayan2704.atlassian.net

Result:

HTTP 400 – The configured Jira domain is not allowed.

PASS

## Regression Test

Existing Jira import functionality was tested using an approved Jira
host.

Existing behavior remained functional.

PASS
