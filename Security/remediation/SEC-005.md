# SEC-005 Remediation Evidence

## Finding
Jira API tokens stored and returned in plaintext

## Severity
High

## CWE
CWE-312 / CWE-200

## OWASP
A02:2021 — Cryptographic Failures

## Original Vulnerability

Jira API tokens were:

1. Stored directly in the Details database table.
2. Returned by GET /api/Auth/details.
3. Passed to the React application.
4. Reused by the frontend when requesting Jira data.

## Remediation

The Jira credential architecture was changed so that the browser works with a
credential ID rather than the Jira API token.

GET /api/Auth/details now returns only:

- id
- domain
- username

Jira API tokens are protected using ASP.NET Core Data Protection before being
stored.

The backend unprotects the token only when preparing the Jira authentication
request.

The API token is never returned to the frontend.

## Files Changed

- Controllers/AuthController.cs
- Controllers/UserStoryDescription.cs
- Models/JiraRequestParams.cs
- Models/JTestCredentialsContext.cs
- Program.cs
- j-test-ui/src/Components/ImportDataSidebar.js
- j-test-ui/src/Components/Settings.js

## Existing Data

Legacy development credentials stored before this remediation were removed and
re-created through the secured credential-save workflow.

No plaintext fallback was introduced.

## Validation

- Backend build succeeds.
- New Jira credential can be saved.
- Database value does not equal plaintext Jira API token.
- GET /api/Auth/details does not return apiToken.
- Browser Jira request contains credentialId, project and issueType only.
- Jira user stories continue to load.
- Source scan confirms the previous API-token URL pattern is absent.

## Functional Impact

Users continue to configure Jira credentials once.

Users are not required to repeatedly enter their Jira username or API token.

Saved credentials can continue to be selected and used for Jira operations.
