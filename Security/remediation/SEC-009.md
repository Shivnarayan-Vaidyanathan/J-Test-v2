# SEC-009 — Cross-Site Scripting (XSS)

## Severity
High

## Classification
- CWE-79: Improper Neutralization of Input During Web Page Generation
- OWASP Top 10: A03:2021 — Injection

## Original Issue
User-controlled and AI-generated content was rendered in the React
frontend using `dangerouslySetInnerHTML` without sufficient sanitization.

This created a risk that malicious HTML, script tags, event-handler
attributes, or other executable browser content could run in the user's
session.

## Remediation
Implemented output sanitization and safe React rendering in `ChatBox.js`.

The remediation includes:

- Added DOMPurify to sanitize AI-generated HTML before rendering.
- AI Markdown is first converted to HTML using `marked.parse()`.
- The generated HTML is sanitized using `DOMPurify.sanitize()`.
- User-entered messages are rendered as normal React text.
- User messages no longer use `dangerouslySetInnerHTML`.
- `dangerouslySetInnerHTML` is retained only for sanitized bot/AI content.
- Existing Markdown/table formatting is preserved after sanitization.
- Malicious `<script>` elements and event-handler attributes are removed
  before bot content reaches the browser DOM.

## Verification

### Positive Test
1. Loaded the Jira User Login story:
   `As a registered user, I want to log in using my email and password so that I can securely access my account.`
2. Sent the story through ChatBox.
3. AI-generated functional test cases were returned successfully.
4. Markdown/table formatting rendered correctly.
5. No JavaScript or React errors occurred.

Result: PASS

### User Script Injection Test
Used the following user-message payload:

`As a registered user, I want to <script>alert('XSS')</script> login using my email and password so that I can securely access my account.`

Expected result:
The `<script>` content is displayed as plain text and no JavaScript executes.

Actual result:
The payload was displayed as user text and no alert popup or script
execution occurred.

Result: PASS

### User Event-Handler Injection Test
Used the following user-message payload:

`As a registered user, I want to <img src=x onerror="alert('XSS')"> login using my email and password so that I can securely access my account.`

Expected result:
The payload is displayed as plain text and the `onerror` handler does not
execute.

Actual result:
No popup or event-handler execution occurred and the application remained
functional.

Result: PASS

### Bot/AI Sanitization Test
A controlled malicious bot response containing a `<script>` element and an
`onerror` event-handler attribute was passed through `DOMPurify.sanitize()`.

Expected result:
Unsafe script content and event-handler attributes are removed while safe
HTML remains renderable.

Actual result:
The safe content rendered successfully, the `<script>` element did not
execute, and the `onerror` attribute did not execute.

Result: PASS

### DOM Verification
Browser developer tools were used to inspect the rendered bot message.

Verified that:

- The `<script>` element was not present in the rendered DOM.
- The `onerror` attribute was removed.
- Safe HTML content remained present.
- No malicious JavaScript executed.

Result: PASS

## Functional Regression
The normal Jira User Login story was tested again after the remediation.

Verified that:

- Jira story loading continued to function.
- Test-case generation continued to function.
- Markdown and table formatting continued to render correctly.
- Existing ChatBox functionality remained unchanged.
- Frontend production build completed successfully using `npm run build`.

Result: PASS
