# SEC-012 — Swagger Security Definition Not Enforced

## Severity
Medium

## Classification
- CWE-306: Missing Authentication for Critical Function
- OWASP Top 10: A05:2021 — Security Misconfiguration

## Original Issue
Swagger exposed a security definition that did not represent an effectively
enforced backend authentication mechanism.

A Swagger security declaration alone does not protect API endpoints. Without
actual ASP.NET Core authentication and authorization enforcement, users could
interpret the Swagger configuration as providing security even though
sensitive endpoints remained callable without valid authentication.

## Remediation
SEC-012 was addressed as part of the SEC-003 JWT authentication and
authorization remediation.

The remediation includes:

- ASP.NET Core JWT Bearer authentication configured in `Program.cs`.
- JWT issuer, audience, lifetime and signing-key validation enabled.
- Authentication middleware added before authorization middleware.
- Sensitive controllers protected using `[Authorize]`.
- Login and Signup explicitly exposed using `[AllowAnonymous]`.
- Swagger security definition changed to HTTP Bearer authentication.
- Swagger configured with `BearerFormat = "JWT"`.
- Swagger configured to send the token using the `Authorization` header.
- Swagger security requirement references the configured Bearer scheme.
- Backend authorization is enforced independently of Swagger.
- Requests without a valid JWT are rejected by ASP.NET Core with HTTP 401.

The Swagger configuration follows this pattern:

```csharp
options.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
{
    Name = "Authorization",
    Type = SecuritySchemeType.Http,
    Scheme = "bearer",
    BearerFormat = "JWT",
    In = ParameterLocation.Header,
    Description = "Enter the JWT bearer token."
});
```

and:

```csharp
options.AddSecurityRequirement(new OpenApiSecurityRequirement
{
    {
        new OpenApiSecurityScheme
        {
            Reference = new OpenApiReference
            {
                Type = ReferenceType.SecurityScheme,
                Id = "Bearer"
            }
        },
        Array.Empty<string>()
    }
});
```

## Verification

### Positive Authentication Test
1. Logged in using valid application credentials.
2. Backend returned a JWT.
3. JWT was supplied using the `Authorization: Bearer <token>` header.
4. Protected APIs accepted the valid JWT.
5. Existing Settings, Jira import and test-case generation functionality
   continued to work.

Result: PASS

### Negative Authentication Test
A protected API was called without a JWT.

Expected result:
HTTP 401 Unauthorized

Actual result:
HTTP 401 Unauthorized

Result: PASS

### Swagger Security Configuration Review
Verified that Swagger uses the HTTP Bearer security scheme and references the
same Bearer scheme in the Swagger security requirement.

Verified that Swagger does not act as the enforcement layer; authentication
and authorization are enforced by ASP.NET Core middleware and `[Authorize]`.

Result: PASS

## Functional Regression
Existing authenticated application functionality was tested after the JWT
and Swagger security changes.

Verified that:

- Login continued to function.
- Protected APIs continued to function with a valid JWT.
- Requests without authentication were rejected.
- Jira import continued to function.
- Test-case generation continued to function.
- Swagger remained usable for authenticated API testing in Development.

Result: PASS
