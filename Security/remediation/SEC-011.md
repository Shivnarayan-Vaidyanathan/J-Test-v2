# SEC-011 — Sensitive / Excessive Logging

## Severity
Medium

## Classification
- CWE-532: Insertion of Sensitive Information into Log File
- OWASP Top 10: A09:2021 — Security Logging and Monitoring Failures

## Original Issue
The backend logged excessive application data and exception details that
could expose sensitive information in application logs.

The affected logging included:

- Full user-story content submitted for test-case generation.
- Full Jira API response bodies.
- Jira API error response bodies.
- Gemini exception messages.
- JWT authentication exception messages.

This created a risk that Jira business data, user-entered content,
authentication diagnostics, or other sensitive information could be retained
in application logs.

## Remediation
Updated backend logging to record only the minimum operational information
required for diagnostics.

The remediation includes:

- Removed full user-story content from application logs.
- Replaced user-story logging with generic test-case generation events.
- Removed full Jira API response bodies from logs.
- Removed Jira API error response bodies from logs.
- Jira success logs now record only the credential ID and operation status.
- Jira failure logs now record only the HTTP status code and credential ID.
- Jira API tokens and Basic authorization credentials are not logged.
- Gemini exception messages are no longer logged.
- Gemini failures record only the exception type.
- JWT authentication exception messages are no longer logged.
- JWT authentication logging uses structured ASP.NET Core logging.
- JWT failures record only the exception type.
- Detailed client exception disclosure remains prevented under SEC-010.

## Verification

### Static Logging Review
A backend-wide search was performed for logging statements:

```powershell
Get-ChildItem -Recurse -Filter *.cs |
    Select-String -Pattern 'LogInformation|LogWarning|LogError|LogCritical'
```

The remaining logging statements were reviewed to confirm that sensitive
user-story content, Jira response bodies, credentials, and tokens were not
written to logs.

Result: PASS

### Sensitive Pattern Search
A backend-wide search was performed for sensitive logging-related patterns:

```powershell
Get-ChildItem -Recurse -Filter *.cs |
    Select-String -Pattern 'ex\.Message|Exception\.Message|Console\.WriteLine'
```

Expected result:
No matches.

Actual result:
No matches.

Result: PASS

### Authentication Logging Test
Logged in using valid application credentials and accessed protected APIs.

Expected result:
Authentication succeeds without logging JWT values, Authorization headers,
passwords, or other credential material.

Actual result:
Authentication completed successfully and no sensitive authentication data
was written to the application logs.

Result: PASS

### Invalid JWT Logging Test
A malformed authentication token was used to access a protected API.

Expected result:
The request is rejected with HTTP 401 Unauthorized and the backend records
only non-sensitive authentication failure metadata such as the exception
type.

The log must not contain:

- The malformed token value.
- Authorization header contents.
- Bearer token contents.
- JWT exception messages.

Actual result:
The protected API rejected the invalid token and sensitive token data was not
written to the logs.

Result: PASS

### Jira Logging Test
Performed the normal Jira User Login story import.

Expected result:
Logs contain only operational information such as Jira request status,
credential ID, and HTTP status code.

The logs must not contain:

- Jira API token.
- Basic authorization credentials.
- Full Jira response JSON.
- Jira issue descriptions.
- Reporter details.
- Jira API error response body.

Actual result:
Jira functionality continued to work and sensitive Jira data was not written
to the application logs.

Result: PASS

### Gemini / User Story Logging Test
Used the User Login story:

`As a registered user, I want to log in using my email and password so that I can securely access my account.`

Expected result:
The backend records a generic test-case generation event without logging the
full user-story text.

Actual result:
Test-case generation completed successfully and the user-story content was
not written to the application logs.

Result: PASS

## Functional Regression
Existing authentication, Settings, Jira import and Gemini test-case generation
functionality was tested after the logging remediation.

Verified that:

- Login continued to function.
- Protected API authentication continued to function.
- Jira User Login story import continued to function.
- Gemini test-case generation continued to function.
- No sensitive credential, token, Jira response or user-story data was
  written to logs.

Result: PASS
