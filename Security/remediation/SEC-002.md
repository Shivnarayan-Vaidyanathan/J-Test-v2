# SEC-002 Remediation Evidence

## Finding
Application passwords stored and compared in plaintext

## Original Severity
Critical

## CWE
CWE-256 / CWE-916

## OWASP
A02:2021 — Cryptographic Failures

## Original Locations
- J-Test/Controllers/AuthController.cs
- J-Test/Models/Credential.cs

## Original Vulnerability
Signup persisted the submitted password directly into the database.

Login compared the submitted password directly against the stored plaintext
password.

## Agent Remediation
ASP.NET Core PasswordHasher<Credential> is now used.

Signup hashes the submitted password before persistence.

Login uses VerifyHashedPassword instead of plaintext comparison.

## Legacy Data
Existing development users containing plaintext passwords must be recreated
after remediation.

No automatic plaintext-password migration was introduced.

## Validation
- dotnet build
- successful signup with new test account
- successful login with correct password
- failed login with incorrect password
- database verification that plaintext password is not persisted
- source scan confirming plaintext comparison was removed

## Functional Impact
Signup and login behavior remains functionally equivalent for newly created
users.

Legacy development accounts must be recreated because their existing
password values were stored in plaintext.

## Status
CLOSED
