# SEC-006 Remediation Evidence

## Finding
Jira API token transmitted in URL query string

## Original Severity
High

## CWE
CWE-598 — Use of GET Request Method With Sensitive Query Strings

## OWASP
A02:2021 — Cryptographic Failures

## Original Locations
- J-Test/Controllers/UserStoryDescription.cs
- j-test-ui/src/Components/ImportDataSidebar.js

## Original Vulnerability
The frontend supplied Jira credentials, including the Jira API token, through
URL query parameters.

Sensitive query parameters may be exposed through browser history, access
logs, proxies, monitoring systems, and other URL-based telemetry.

## Agent Remediation
Changed the frontend-to-backend Jira operation from GET with query parameters
to POST with a JSON request body.

The backend now accepts JiraRequestParams using FromBody.

The Jira API token is no longer included in the J-Test endpoint URL.

## Files Changed
- J-Test/Controllers/UserStoryDescription.cs
- j-test-ui/src/Components/ImportDataSidebar.js

## Validation
- dotnet build
- frontend build attempted
- searched source for apiToken query-string construction
- verified backend uses FromBody
- verified Jira operation uses POST

## Baseline Limitation
The frontend production build had a pre-existing dependency failure involving
the marked package before SEC-006 remediation.

If the same failure remains, it is not attributed to this remediation.

## Functional Impact
The frontend continues to request Jira user stories through the J-Test
backend.

The frontend/backend transport changed from GET query parameters to a POST
JSON body.

## Status
CLOSED
